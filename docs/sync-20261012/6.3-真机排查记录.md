## 回归 ② 结论：不是回归，是并发争抢 CPU

    与基线并发：启动 2-4 分钟后内存仅 10.3 GiB，37 分钟仍未就绪
    独占运行　：启动 2 分钟后内存 89.84 GiB，13 分钟就绪

"随机初始化 63 GB 文本编码器"是这条链路的固有代价，非本次合并引入。

## 回归 ③：同 seed 冷热不一致（可复现，未定位到代码行）

对照（a100-0008，生产档，同输入 1344x768/5s/num_frames=120/seed=42）：
  基线 origin/main（旧镜像）：冷 md5 == 热 md5 == b5991b76...（2,176,426 B）>> 一致
  新镜像（生产档 + 编译开）：
      请求1 b5991b76 之外 -> 8adbf474 / 05fb7676 / b14eaf1a / d5717aad   （每次服务重启后的首请求都不同）
      请求2/3          -> c8d79ff0（两次完全一致）
  新镜像（diffusion_compile_granularity: none，编译关）：
      请求1 -> c443e03a     请求2 -> a037ef2a        >> 关编译仍不一致

结论：
  * 规律 = "服务启动后的第一个请求"与后续请求不同；热态之间稳定。
  * 共 6 次独立复现（含关编译 1 次）。
  * 与 torch.compile 无关（关掉仍复现）。
  * 契约层无差异（geometry/packing/rng dump 逐字段一致）——非我方几何/打包/RNG 抽序。
  * 违反手册硬性要求：line 39 / 61 / 325「同 seed 下逐位一致」。
  * 生产影响：同 seed 重跑，结果取决于服务是否刚启动。
