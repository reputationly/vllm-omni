# MiniMax-H3 FL2VA 剪枝 r8 对比结论（2026-08-20）

## 1. 结论先行

在这组严格相同请求的 Modular Diffusers 单卡自动卸载测试中，`MiniMax-H3-Pruned-r8` 的三个档位都能完成生成，输出规格完整，提示词要求的舰桥、女舰长、舰队充能、约 4.5 秒闪光/切镜均保留；没有发现静帧层面的结构崩坏。Turbo8 与原权重最接近，Turbo4 有更明显的服装颜色、肩部细节和脸部纹理差异；Base 20 的人脸与制服差异也明显。因此当前结论是“具备继续接入和现网 A/B 的资格”，不是“已经证明主观质量完全等价”。最终质量门禁仍需逐段播放检查人物稳定性、运动连续性、闪烁和音画观感。

显存收益有限但稳定：Base 的 SMI 峰值少 904 MiB，两个 Turbo 少 1020 MiB；PyTorch 峰值分别少 0.736 GiB、1.061 GiB。模型快照表观占用从 124 GiB 降到 75 GiB，transformer 从 62 GiB 降到 38 GiB。

墙钟耗时明显下降，但不可直接当作线上 TP4 加速比：本测试使用单卡组件自动卸载，首次 DiT forward 会受 CPU/NFS 页缓存、group-offload trace/prefetch 影响。Base 与 Turbo4 的大部分墙钟优势来自剪枝权重首步显著更快；进入稳定步后，剪枝每步约快 4%～15%。线上结论必须在 vLLM-Omni 的 3+2/TP4 实现完成后另做热态压测。

## 2. 可比条件与有效性

六发正式结果完全使用同一个 `manifest_t2va_640x384.json`：

- workflow: T2VA / FL2VA 无首尾帧
- 提示词：官方星舰舰桥示例，包含两个 shot 和 4.5 秒切镜
- 640×384、124 帧、24 fps、约 5 秒、seed 0
- Base：20 次真实 transformer forward，video/audio shift = 12/3
- Turbo8：8 次真实 forward，官方 Turbo8 LoRA，shift = 12/3
- Turbo4：4 次真实 forward，官方 Turbo4 768p LoRA，shift = 6/3
- 官方与剪枝只替换 transformer 权重；文本、VAE、音频组件、scheduler、请求和编码流程相同
- 所有正式路径只引用 `/nfs-models/wuhanjisuan894/models`，不依赖 `/nfs-data`

有效性保护：harness 对 transformer forward 次数做硬断言；Turbo LoRA 以显式 PEFT adapter 加载，并逐张量验证。Turbo8/4 都是 624/624 张量精确匹配、312 个 target、rank 128；alpha 分别为 8 和 128，对应 effective scale 0.0625 和 1.0。

两组早期结果不得用于结论：`invalid_no_lora_20260820_0710/` 实际没有加载 LoRA；`invalid_wrong_schedule_20260820_0737/` 把 scheduler grid points 当作 NFE，实际少跑一步且 Turbo4 shift 错误。两组均原样归档，未混入下表。

## 7. 静态目检

- Base 20：前半段舰桥、人物背影、舰队与充能过程一致；两者都切到舰长近景。剪枝版近景制服加入明显红色领片，脸型/发型和背景也有差异，属于不可忽略的生成差异。
- Turbo8：构图、人物、充能、闪光、切镜和近景身份最接近；差别主要在领口、颜色和细部纹理。
- Turbo4：主流程和切镜均保留，但制服色彩、肩部轮廓和脸部纹理差异比 Turbo8 更明显。
- 三组静帧都未见黑帧、冻结、内容消失或结构崩坏。视频级闪烁、人物运动稳定和主观音质仍须播放原视频确认。

## 8. 是否进入 vLLM-Omni

建议：允许进入下一阶段的引擎适配与 A/B，不建议直接替换线上默认权重。先完成人眼视频门禁，再实现剪枝 AdaLN 路径，然后在同一 3+2/TP4 部署下测热态首包、总耗时、每卡峰值、吞吐和并发。

需要特别纠正原交接中的一句话：当前 vLLM-Omni 并未自动支持剪枝 AdaLN。剪枝配置保留 `time_embed_dim=2688`，另有 `adaln_rank=8`；checkpoint 使用 `[1025,8]` 的 fp32 timestep table、`[8,2688]` basis、fp32 mean/folded_bias，以及 8 宽无 bias 投影，且不应再做 SiLU。引擎适配必须显式接入这些语义并沿用 checkpoint table，不能只改张量宽度。
